# WealthPilot 完整说明

这是详细版：每项功能是怎么做的、全部命令、全部接口、配置项、数据来源。只想快速了解，看 [README](../README.md)。

## Why WealthPilot?

大多数投资分析工具只是简单地调用一次 LLM 生成文本。WealthPilot 不同——它是一个**完整的多智能体系统**，先把问题里的证券名解析成确定的代码，Planner 按研究模板或自由规划拆出任务图，7 个按研究维度分工的 Agent（基本面 / 估值 / 走势 / 行业 / 选股 / 组合 / 基金）并发取证，Critic 双闸门审核证据与回答，通过后才发布结论 —— 每个数字都能追溯到一次工具调用。

**给谁用**：有一定投资经验、但还没有自己一套体系的人——平时用同花顺、东方财富看盘和下单，买卖的理由却常常是“看到有人说好”。行情软件你已经有了，这里不重复它；这里做的是它不做的那一段：把一只股票研究清楚、把“为什么买、什么情况下算我错了”写成能核对的判断、到期回头看对不对。

以 **A 股个股**为主导，港股和美股能查能研究；基金保留为持仓的一种。

| 5 | **市场** → 选股器 → 筛选、回测这组条件 | 筛选结果，以及把同样的条件放回过去两年的表现（附带一串局限说明） |
| 6 | **持仓** → 模拟盘 | 两笔成交和一笔被 T+1 规则拒掉的委托 |
| 7 | **研究** → 点带「高股息检查」的那一条 | 一次按用户自写方法做的研究：只派了方法里指定的两个 Agent，报告按方法里的章节写；问题开头那句“记住……”进了「AI 记住的事」 |

## Quick Start

### 一条命令装好（推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/Jackychen-12/wealthpilot/main/scripts/install.sh | bash
```

```bash
wealthpilot setup    # 选一家模型、贴一个 Key、放进你的股票，一分钟
```

```bash
wealthpilot          # 开始用
```

机器上只需要有 git 和 curl。安装脚本做四件事：

1. 没有 uv 就先装一个（Python 的包管理器；装在你的用户目录下，不动系统里的 Python，不要管理员权限）；
2. 把代码放到 `~/.wealthpilot/app`；
3. 装依赖。机器上有 Node.js 就顺手把网页版构建出来，没有也不影响终端使用；
4. 在 `~/.local/bin` 放一个 `wealthpilot` 命令。

你的东西——配置、数据库、研究方法——都在 `~/.wealthpilot`，和代码分开，升级、重装、卸载都不会动它。脚本可以重复运行，第二次就是更新。卸载：`bash ~/.wealthpilot/app/scripts/install.sh --uninstall`（只删代码和命令，数据留着）。

手上已经有 Key，可以装的时候一起配好，装完直接用：

```bash
curl -fsSL https://raw.githubusercontent.com/Jackychen-12/wealthpilot/main/scripts/install.sh | WEALTHPILOT_KEY=sk-xxxx bash
```

**Windows** 用 PowerShell 版，做的是同样四件事（命令放在 `%USERPROFILE%\.local\bin`，会把这个目录加进你自己的 PATH）：

```powershell
irm https://raw.githubusercontent.com/Jackychen-12/wealthpilot/main/scripts/install.ps1 | iex
```

如实说明：这个脚本是照着 `install.sh` 写的，**还没有在 Windows 上实际跑过**——开发用的机器上没有 PowerShell。测试只能钉住几条写法上的坑（不带 BOM、不用会关掉窗口的 `exit`、和 `install.sh` 认同一套环境变量）。装不上的话把报错发到 issue；在那之前 WSL 里用上面的 `install.sh` 是稳妥的路。

这样写 Key 会留在终端的历史记录里，介意的话还是用 `wealthpilot setup`，那里粘贴的时候不回显。想换安装位置、换分支、不构建网页版，脚本开头的注释里列了对应的环境变量。

### 配好模型：`wealthpilot setup`

三步，每一步都能回车跳过，之后随时重来：

1. **用哪家的模型**。列出能接的服务，选一个，粘贴 Key（输入不回显；只存在这台电脑上，文件权限 600）。然后问你要不要当场测一次——那会真的调用一次模型，花几十个 token，不想花就答 n。
2. **放进你的股票**。`贵州茅台 100 1500; 600036 2000 35.2` 这样写，认成了哪只股票、多少股先给你看，点头才写入；或者输入 `s` 用示例数据。
3. 告诉你下一步敲什么。

不想被提问（写进脚本、在远程机器上）就把参数给全：

```bash
wealthpilot setup --key sk-xxxx                                          # 只给 Key：按前缀认出是 DeepSeek 还是 Claude
wealthpilot setup --provider zhipu --key xxxx                            # 指定服务，接口地址和默认模型名自动填好
wealthpilot setup --provider ollama --model qwen2.5:14b                  # 本机模型，不要 Key
wealthpilot setup --base-url http://localhost:8080/v1 --model my-model   # 清单之外的兼容服务
```

能直接叫出名字的服务（`wealthpilot model list` 看得到同一张表，网页「设置」里也是这一份）：

| `--provider` | 服务 | 预填的模型名 |
|---|---|---|
| `deepseek` | DeepSeek | `deepseek-chat` |
| `claude` | Claude（Anthropic） | `claude-sonnet-5-5` |
| `siliconflow` | 硅基流动 | `deepseek-ai/DeepSeek-V3` |
| `zhipu` | 智谱 | `glm-4-flash` |
| `moonshot` | Moonshot（Kimi） | `moonshot-v1-32k` |
| `dashscope` | 阿里云百炼（通义） | `qwen-plus` |
| `ark` | 火山方舟（豆包） | 填你在方舟控制台建的接入点 ID |
| `openrouter` | OpenRouter | `deepseek/deepseek-chat` |
| `openai` | OpenAI | `gpt-4o-mini` |
| `ollama` | 本机 Ollama | `qwen2.5:14b` |

如实说明：我们自己长期跑的只有 DeepSeek。其余各家预填的是接口地址和一个通常能用的模型名，没有逐个实测过，各家的模型名也经常换——配好后跑一次 `wealthpilot model test`，不通就照服务商文档里的名字用 `--model` 改。唯一的硬要求是模型得支持工具调用（function calling），不然 Agent 取不了数。

### 装好之后

`wealthpilot` 一条命令同时给你三样东西：

- **终端**：当前窗口里直接提问、用 `/` 命令；
- **网页版**：后台带起 http://localhost:8000 （接口和页面同一个端口，不用另开前端）；
- **每日盯盘**：跟着这个进程跑，错过的那次（合盖、关机）下次启动时会补上。

没跑过 `setup` 直接敲 `wealthpilot` 也行：没配模型或没有股票时，进来会带你走同样的三步。网页首页也有一张「开始使用」卡片，列着配置模型 → 放进你的股票 → 做第一次研究 → 连上手机（可选）各自做没做、下一步点哪里。

不进界面也能办的事：

| 命令 | 做什么 |
|---|---|
| `wealthpilot status` | 现在是什么情况：模型配没配、几只持仓、盯盘开没开、手机绑没绑、今天用了多少 token |
| `wealthpilot model` | 现在用的是哪个模型。`model list` 看能接哪些，`model set <服务> --key <Key>` 换一个，`model test` 实测一次 |
| `wealthpilot config list` | 看全部配置（Key 只显示末四位）。`config get <名字>`、`config set <名字> <值>` 改一项，`config path` 看配置文件在哪 |
| `wealthpilot import 持仓.txt` | 从文件录入持仓，每行「名称或代码 数量 成本价」。先给你看认成了什么再问；管道用 `-`，加 `--yes` 不问 |
| `wealthpilot skills gallery` | 现成的研究方法。`skills install <名字或 https 链接>` 装上，`skills list` 看已有的，`skills remove <名字>` 删掉 |
| `wealthpilot model fallback <服务>` | 设一个备用模型：主模型余额不足、Key 失效、被限流、连不上时，这一轮自动换过去（`off` 关掉） |
| `wealthpilot sessions` | 以前的会话。`sessions 宁德时代` 只列提到过它的；`wealthpilot -c` 进来就接着上一个会话聊 |
| `wealthpilot channels` | 手机上的渠道卡在哪一步。`channels setup telegram --token …` 配置，`channels pair telegram` 出配对码，`channels test telegram` 发一条试试 |
| `wealthpilot backup` | 把数据库、配置、研究方法打成一个文件（`--no-keys` 不带 Key）。`wealthpilot restore <文件>` 放回来，恢复前会先自动备份现状 |
| `wealthpilot recap` · `wealthpilot macro` | 今天的大盘复盘（涨停、连板、题材热点、龙虎榜、市场情绪）· 宏观数据。都不调用模型 |
| `wealthpilot trades 交割单.csv` | 交易行为诊断：从你自己的成交记录里找追涨、交易过频、亏损加仓、处置效应这类行为偏差。记录不保存 |
| `wealthpilot persona` | 回答风格：你希望它怎么跟你说话。`persona use friend` 用现成的，`persona set "…"` 自己写，`persona clear` 清掉 |
| `wealthpilot logs` | 后台出了什么事：研究失败、推送没发出去、盯盘出错。`--errors` 只看出问题的，`-f` 跟着看 |
| `wealthpilot doctor` | 哪里不通：逐项检查模型、数据源、数据库、网页版、手机渠道、版本、日志，不通的每一项都附修法 |
| `wealthpilot update` | 升级（先备份数据库） |
| `wealthpilot completion zsh` | 生成按 Tab 补全命令的脚本（也有 `bash`） |

只想要终端：`wealthpilot --no-web`；端口被占：`wealthpilot --port 8001`。

一点如实说明：电脑合盖休眠时进程会被挂起，盯盘和进行中的研究都会停，软件层面拦不住；能做的是醒来后把错过的那次盯盘补上。要它全天候跑，需要放在一台不休眠的机器上（见 Docker 部署），再用 `wealthpilot --server` 连过去。

### 从源码装（想改代码的人）

```bash
git clone https://github.com/Jackychen-12/wealthpilot.git
cd wealthpilot

make setup      # 装依赖、构建网页版
make install    # 把 wealthpilot 装成全局命令（指向这个仓库，代码改了不用重装）
wealthpilot setup
```

这种装法下，配置、数据库、技能文件都在仓库的 `backend/` 里（或 `WEALTHPILOT_HOME` 指定的目录），和你在哪个目录敲命令无关。没装全局命令时用 `make start`，效果一样。开发用 `make dev`，地址也是 http://localhost:8000 ——后端热重载，前端代码改了会自动重新构建，刷新页面即可；只有需要逐像素调界面时才用 `make workbench`（Vite 热更新，:5180）。仓库挪了位置，全局命令会直接告诉你去新位置重新 `make install`；`make uninstall` 移除。

以前从源码装过、现在想换成一条命令的装法：先在仓库里打一份备份（`cd backend && uv run wealthpilot backup ~/wp.tar.gz`），装完后 `wealthpilot restore ~/wp.tar.gz`，原来的持仓、研究记录、配置和研究方法就都带过去了。换电脑也是这两步。

### Docker Compose

```bash
git clone https://github.com/Jackychen-12/wealthpilot.git && cd wealthpilot
cp backend/.env.example backend/.env
# 编辑 backend/.env 填入 API Key
docker compose up --build -d
# 网页版和接口都在 http://localhost:8000 （接口文档 /docs）
```

### 在网页上配置

启动后打开工作台左侧「设置 → 设置」：选模型提供商、填 API Key、开关个人模式 / 模拟盘 / 每日盯盘、填推送地址，保存后立即生效，不用重启。写入的和 `wealthpilot setup`、`wealthpilot config set` 是同一个文件（`wealthpilot config path` 看它在哪）。这个接口只允许从运行后端的那台机器访问；Key 只写不读，页面上只显示是否已配置和末四位。由进程环境变量指定的项（比如 Docker 里）会标注出来，网页上改不了。

### 配置 AI 提供商

三种接法：Claude、DeepSeek，或任何兼容 OpenAI 接口的服务（`AI_PROVIDER=openai`，含本机 Ollama）。用 `wealthpilot setup` 或网页「设置」配就行，下面是它们写进配置文件的内容，想手改的时候看：

**选项 A — Claude**
```env
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-xxx    # 从 https://console.anthropic.com/ 获取
```

**选项 B — DeepSeek（国内可用，成本更低）**
```env
AI_PROVIDER=deepseek
DEEPSEEK_API_KEY=sk-xxx         # 从 https://platform.deepseek.com/ 获取
```

常用可选项（完整列表见 `backend/.env.example`）：

| 变量 | 默认 | 说明 |
|------|------|------|
| `AGENT_MAX_TOKENS` | 16000 | 单次模型输出上限。默认开启思考的模型，思考 token 也计入此值，设太小回答会被截断 |
| `AGENT_MAX_TOOL_ROUNDS` | 3 | 每个 Agent 的工具调用轮次；用完后强制基于已有证据作答 |
| `CRITIC_ENABLED` | true | 关闭后跳过证据审核与回答校验（不建议） |
| `CRITIC_MIN_GROUNDING_RATE` | 0.9 | 重写用尽后，数字溯源率不低于此值的草稿带标注发布；设为 1 则一律拒答 |
| `RUN_TIMEOUT_SECONDS` / `AI_TIMEOUT_SECONDS` | 180 / 60 | 整轮研究 / 单次模型请求的超时 |
| `LOCAL_USER_ID` | 0 | CLI 与 MCP 读取哪个用户的持仓和画像（0 = 未登录的匿名档） |

配置完成后运行 `wealthpilot status` 看一眼。占位值（`sk-ant-xxx`）会被视为未配置。

## Architecture

### 多智能体系统

WealthPilot 的 AI 核心是 **证券解析 + Planner + 9 个专业 Agent + 多空辩论 + Critic + Synthesizer** 的协作流程，不是单次 LLM 调用：

```
用户消息
   │
   ▼
┌──────────────────┐
│ 证券解析（纯代码）│  「宁德时代」→ 300750（股票）；Agent 只许用解析出的代码

       ▼
┌──────────────────┐
│  Planner         │  意图识别：命中研究模板 → 代码生成任务图 + 固定章节

└──────┬───────────┘

       ├─────────┬─────────┬─────────┬──────────┬──────────┬──────────┐   （个股深度研究：这六个并行）
       ▼         ▼         ▼         ▼          ▼          ▼

       ▼
┌──────────────────┐   不足 → 补充任务重跑（最多 CRITIC_MAX_REPLANS 轮）
│ Critic 闸门 A    │   固定模板：按“哪个工具取到了数据”由代码判定；自由问题：一次小额 LLM 调用
└──────┬───────────┘
```

**研究模板（Playbook）**

| 模板 | 触发 | 任务图 | 固定章节 |
|---|---|---|---|
| `stock_deep` 个股深度研究 | 一只股票 + 综合性问题 | 基本面 ∥ 估值 ∥ 走势 ∥ 行业 | 结论 / 基本面 / 估值 / 走势 / 行业位置 / 风险 / 待验证 |
| `stock_compare` 个股对比 | 两到三只股票 | 每只各跑 基本面 ∥ 估值 | 对比表 / 各自强弱 / 结论 |
| `holding_review` 持仓诊断 | 「我的持仓 / 组合」 | 组合 → 对重点持仓跑 基本面 ∥ 估值 | 组合概况 / 集中度与回撤 / 重点持仓 / 约束校验 |
| `screen` 选股 | 含筛选条件 | 选股 → 对候选跑 估值 | 条件复述 / 候选表 / 逐只要点 / 局限 |
| `review` 事后复盘 | 「复盘」「之前的判断准不准」 | 复盘 Agent | 成绩 / 成立 / 证伪 / 启示 |
| 自由问答 | 其他，或只问一个点 | LLM 拆解，通常 1–2 个 Agent | 自由 |

**关键设计**

1. **按研究维度分工，不按资产类型**：基本面、估值、走势、行业互不依赖，天然可以并行；每个 Agent 的工具集小，模型不容易选错。组合与风险共用同一批计算工具，合成一个 Agent。
2. **证券解析在规划之前**：名称 → 代码由搜索接口确定，写进每个子任务的上下文；模型不凭记忆写代码。
3. **固定套路走固定流程**：四类常见问题由代码生成任务图，同一类问题每次的拆法和报告结构一致。
4. **真并发**：`BaseAgent.run` 是 async 的；同一轮内的多个工具调用用 `asyncio.gather` 并发。同步 SDK 通过 `streaming.py` 搬到工作线程，不阻塞事件循环。
5. **证据是一等公民**：工具结果连同证据 ID 一起交给模型，回答逐行引用 `[E-…]`；同一轮研究内相同的工具调用只执行一次，并有调用次数与超时预算。
6. **宁可不答，不可乱答**：Critic 不通过、任务失败、输出被截断或被拒绝时，系统发布的是"为什么没有结论"，而不是未经校验的草稿。
7. **只陈述事实与推断**：不给目标价，不做确定性的涨跌预测；财务数字必须带报告期。
8. **风险画像是硬约束**：`InvestorProfile` 注入 Planner / 各 Agent / Synthesizer。未完成测评时，不得给出具体仓位比例或止损价位。
9. **算术不交给 LLM**：占比、变动后的集中度、仓位上限、选股筛选都由确定性代码计算。

**评测**（`backend/scripts/eval.py`，12 题，DeepSeek 真实模型，2026-10-04 各跑一次）

| 指标 | 重构前（5 个按资产分的 Agent） | 现在（7 个按维度分的 Agent + 模板） |
|---|---|---|
| 通过校验 | 4 / 12 | 9 / 12 |
| 带标注发布（partial） | 7 | 3 |
| 未发布 | 1 | 0 |
| 平均被打回次数 | 1.83 | 1.33 |
| 平均耗时 | 25.7 秒 | 36.8 秒 |
| 平均工具调用 | 9.2 | 11.1 |

样本只有 12 题、每版只跑一次，模型输出有随机性，这组数字说明方向而不是精确幅度。代价是深度研究更慢（一次要跑四个 Agent）。评测后又收紧了规划提示：只问单一维度的问题（如"最近业绩怎么样"）不再走深度研究模板。复现：`uv run python scripts/eval.py --out new.json`，对比用 `--compare old.json new.json`。

打开个人模式（回答要多写一节立场与建议）后一度掉到一半左右：模型做对比时会现算差值和变化率（“毛利率从 26.27% 降到 23.93%，下降 2.34 个百分点”），这些数不在工具返回里，被当成编造反复打回。现在的规则是：一个数如果能由**同一行或上一行**里已溯源的两个数一步算出来（差、和、比、变化率），就算有据可查——操作数就写在旁边，读者可以自己核对；离得远的、凭空出现的仍然打回。改完后在个人模式下重跑同一套 12 题：通过 9、带标注发布 3、未发布 0，平均 40 秒。

## 和行情软件有什么不一样

行情、图表、数据的广度，同花顺和 Wind 做了二十年，这里不比这个。WealthPilot 做的是行情软件不做的三件事，并且把它们放在界面最前面：

| | 行情软件 | WealthPilot |
|---|---|---|
| 结论从哪来 | 给你所有的数，结论自己下 | 给结论，每个数字能点回原始数据；证据不够就不发布 |
| 说过的话算不算数 | 不记得你当时怎么判断的 | 每次研究留下验证点，到期由代码核对成立还是被证伪，累计成成绩单 |
| 围着谁转 | 围着全市场 | 围着你的持仓和自选：每天自己检查它们发生了什么，有事才找你 |

落到界面上：

- **首页是工作台，不是行情首页**。最上面是提问框和四个待办数字（等你决定的建议、被证伪的判断、待核对的验证点、还没研究过的股票）；然后是“我的股票”一张表——每只股票的涨跌、持有收益、PE 历史分位、当初的判断现在成立几条、最近一次研究是哪天；再是今天发生了什么。大盘、行业热力图、涨跌榜放在后面。
- **个股页先给判断卡**。当前的结论和立场、是哪天下的、之后验证得怎么样；有判断被证伪时直接提示“这个结论是在那之前下的，建议重新研究”。没研究过就是一个“一分钟出研究”的入口。
- **K 线上标着你做研究的日子**。行情软件画不出这条线，因为它不知道你什么时候下过判断。

基础的行情展示也补了：日 / 周 / 月 K 线（蜡烛、MA5 / MA20、成交量）、今开最高最低振幅、估值五年走势、利润率与负债率走势、行业热力图、涨跌榜、持仓分布与盈亏图。免费数据源做不了的没有硬做：分时图、Level-2、资金流向。

## 投研工作台

`wealthpilot`（或 `make start` / `make dev`）启动后打开 **http://localhost:8000**。这是日常使用的入口：桌面端布局，所有数字都来自后端实时计算，接口失败就显示失败，不会回退成示例数据。

左边栏只有五项，加一个设置。其余页面都是这五项下面的页签——一个投资者平时就做这五件事，不该为了找一个功能去翻二十几个入口。

| 左边栏 | 回答什么问题 | 下面的页签 |
|---|---|---|
| **今日** | 我的股票现在怎么样，有什么等我处理 | 没有页签，一页看完：提问框、等你处理的事（没有就不显示）、“我的股票”一张表（涨跌 / 持有收益 / PE 分位 / 当初的判断 / 最近研究）、今天它们出了什么事、大盘一行 |
| **研究** | 这只股票怎么样 | 提问（自由提问，右侧实时显示解析出的证券、任务规划、每条证据、Critic 的通过 / 打回）· 研究记录（回看任何一次的回答与证据，可存成 Markdown / PDF）。个股和基金的详情页也算在这里，从搜索框或任何一张表点进去 |
| **市场** | 今天市场本身怎么样 | 大盘（指数与涨跌家数、涨停与题材、行业热力图、涨跌幅榜）· 宏观 · 选股器 |
| **持仓** | 我手上有什么，风险在哪 | 持仓（明细、分布、收益与归因）· 自选股 · 风险体检（回撤、集中度、相关性、预警） |
| **回顾** | 我之前判断得对不对 | 验证与回溯（验证点成绩单、立场回溯、建议单的授权）· 交易行为诊断（买入理由对账、成交记录诊断）· 周报 |
| 设置 | — | 基本设置（模型、手机渠道、回答风格、预算）· 研究方法 · 记忆 · 风险画像 · 自动任务 · 数据连接（数据从哪来、现在通不通）· 审计日志 · 名词解释 · 更多工具 |

「更多工具」里是不在主线上的几样：模拟盘、调仓推演、压力测试、持仓穿透、规则回测、基金查询。功能和地址都没变，只是不占侧栏和页签的位置——主线是“研究一只股票 → 留下可核对的判断 → 到期回头看”，这几样用得上的人少。

## 个股：A 股为主，港股和美股能查能研究

个股是现在的主线。A 股最全；港股、美股从 0.10.0 起能搜、能看、能做深度研究，但数据比 A 股少，见这一节末尾。

- **个股深度研究**：问"帮我分析一下宁德时代"，基本面、估值、走势、行业、资金与筹码、预期与消息六个 Agent 并行取证，看多看空两方先辩一轮，再按固定章节成文，每个数字带证据。
- **估值历史分位**：PE / PB / PS 在近五年自身历史里的位置，以及在同行业盈利公司里的 PE 排名与行业中位数。
- **多期财务指标**：营收、归母与扣非净利润、ROE、毛利率、净利率、资产负债率、每股经营现金流，每条带报告期；另有分红记录。
- **选股**：全市场约 5500 只股票的估值与最新一期业绩快照，按条件确定性筛选；行业涨跌排行按成分股涨跌幅中位数统计。
- **历史行情打通**：持仓里的股票 / ETF 走前复权日线，和基金净值用同一种结构，回撤、Sharpe、相关性、健康度、压力测试都会把它们算进去。
- **穿透合并直接持股**：直接持有的个股会和基金重仓股里的同一只票合并，一眼看出"我直接买了茅台，基金里又间接持有多少"。
- **老工具兼容股票**：区间收益、最大回撤、规则回测带 `asset_type` 参数；股票回测默认计入 0.1% 单边费用，并在局限说明里写明未处理停牌与涨跌停。

几点如实说明：

- 估值分位只和**自己的历史**比，不代表绝对便宜或贵；亏损期 PE 为负，没有可用的分位。
- 财务数据是滞后数据，各期金额为累计值；选股用的 ROE 与增速取自最新一期报表。
- 行业分类来自东方财富的板块归属；行业涨跌是成分股涨跌幅的中位数，不是行业指数。
- **没有做资金流向**：对应的免费接口实测频繁断连，宁可不做也不给不稳定的数。
- 数据都来自公开的网页接口，没有服务保障，会断——见下面[数据从哪来，断了怎么办](#数据从哪来断了怎么办)。
- 不给目标价，不做买卖点预测。

**港股和美股**。搜索框、`/stock`、手机里都认 `00700.HK`、`AAPL.US`、`$AAPL` 和中文名（腾讯控股、苹果）。有的：行情和前复权日线（腾讯财经，行情和美股日线有新浪作备用）、主要财务指标（东方财富，港股按报告期、美股按财年和季度，金额带币种）、市盈率和市净率在近五年自身历史里的分位（百度股市通）、公司简况、反向 DCF、新闻，以及在这些数据上的技术指标、区间收益、回撤。深度研究会自动换成一套只用这些数据的计划（基本面、估值、走势、预期与消息四个方面），不会去调 A 股才有的工具然后报一堆“未获取到”。

**港股美股可以记进持仓**。持仓这本账是人民币的——市值、盈亏、占比、风险都是人民币——所以要折算：成本价照券商里看到的港元或美元填，入账时按**买入那天**的人民币汇率中间价折成人民币（休市日取之前最近的一个工作日），现价按今天的中间价折。持仓页上人民币的数下面有一行小字，写着原币种的数和用的汇率，比如“HK$380 × 0.86897”。两件事要知道：成本既然按买入日的汇率折了，盈亏里就包含汇率的涨跌，不只是股价的；港股通实际结算用的是结算汇率，不是中间价，这里的数和券商账户里的会差一点。取不到汇率时这笔持仓记不了、估不了值，不会拿原币种的数混进人民币的账。

**和同行比：你点名，它取数**。港股美股没有靠谱的免费行业分类，而且同行本来就跨市场——腾讯的同行是阿里、美团、Meta。所以没有去凑一个分类库，而是加了 `compare_stocks`：给 2 到 6 个代码（A 股、港股、美股可以混着），返回市值、市盈率、市净率、各自的五年分位、最近一期的营收和利润增速、ROE、毛利率、负债率。拿谁当同行是一个判断，由模型提名并在报告里写明理由，可以被质疑；表里的数字各有出处。不同货币的市值不能直接比大小，这一点工具的返回里写着。

没有的，问到会直说：市销率分位、按行业分类自动找的同行、资金流向、龙虎榜、股东与机构持仓、一致预期、公告正文、选股。A 股软件里的“主力资金流向”是按单子大小估出来的，港股美股没有这个东西，这里不硬造；对应的真实数据（港股通持股变化、美股的机构持仓和内部人买卖）还没有接。

### 数据从哪来，断了怎么办

行情、财务、估值全部来自公开的网页接口。它们没有服务保障：对方改版、限流、临时故障，哪一样都会让一路数据断掉。写这一节的当天（2026-10-09）就碰上一次——腾讯原来的日线接口被它自己的防火墙拦了，返回 501；东方财富的日线同时断连。在这之前，A 股日线悄悄退到了最后一个备用源（不复权价），港股美股的日线干脆取不到，而界面上没有任何地方会告诉你。

所以现在的做法是把“会断”当成常态：

| 数据 | 先用 | 不通换 | 备注 |
|---|---|---|---|
| A 股实时行情 | 腾讯财经 | 新浪财经 | 备用源没有市盈率和市值，这几项留空，不估 |
| A 股日线（前复权） | 腾讯财经（两个入口） | 东方财富 → 新浪财经 | 最后一个是不复权价，会标出来 |
| 财务指标 | 东方财富数据中心 | 新浪财经 | 两家的十二项指标对过数，完全一致 |
| 估值历史与分位 | 东方财富数据中心 | 百度股市通 | 备用源点稀一些，没有市销率和行业归属 |
| 公告 | 东方财富 | **巨潮资讯**（证监会指定的披露网站） | 备用源给的是官方 PDF 的链接，暂时读不了正文 |
| 融资融券 | 东方财富数据中心 | **沪深交易所**每天公布的明细 | 两边的数对过，一致。交易所那份没有占流通市值的比例，深市只取最近一个月 |
| PMI、物价、货币、GDP | 东方财富数据中心 | 新浪财经 | 备用源只有制造业 PMI、CPI、M1 / M2、GDP（对过数，一致）；它的非制造业 PMI 和 PPI 停在 2019 年，不拿来用 |
| LPR | **中国货币网**（全国银行间同业拆借中心） | 东方财富数据中心 | |
| 社会融资规模 | **中国人民银行**官网的统计表 | 商务部商务数据中心 | 备用源经常晚几个月，晚了会写明 |
| 汇率（港元、美元兑人民币） | **中国货币网**的人民币汇率中间价 | 新浪财经 | 备用源是即时汇率，不是中间价，也没有历史 |
| 港股、美股行情 | 腾讯财经 | 新浪财经 | 两家的市盈率口径不一样（阿里巴巴同一天一家 24 倍一家 16 倍），备用源的市盈率不拿来用 |
| 港股、美股日线 | 腾讯财经 | 新浪财经（只有美股，不复权） | 港股日线只有腾讯 |
| 港股、美股估值历史 | 百度股市通 | — | 只有这一个来源 |
| 分红、股东户数、十大股东、机构持仓、主营构成 | 东方财富数据中心 | — | 只有这一个来源。按报告期更新，取不到时用上一次取到的，最多留五个月 |
| 一致预期、研报 | 东方财富数据中心 | — | 只有这一个来源。取不到时用上一次取到的，最多留一个半月 |

加粗的是发布方自己或监管指定的渠道。

- **自动换**。主来源出错（连不上、超时、返回的结构不认识）就换下一个；一个来源连续失败两次，先跳过它两分钟，不让每个请求都把超时等一遍。“这只股票本来就没有这项数据”不算出错。
- **认得出改版**。字段数变了、报表改名了、JSON 里找不到该有的那一层，都会记成“结构变了”，而不是悄悄返回空。
- **都不通时用上一次的，并写明日期**。每类数据取到之后会留一份；全部来源都取不到时拿它顶上，交给模型的结果里带一句“数据源这次取不到，用的是 10-07 16:26 取到的那一份，引用时写明日期”。从没取到过的，照旧如实说没有。
- **少打扰对方**。同一份数据短时间内只取一次（一次研究里几个 Agent 常常要同一只股票的行情和财务）；对东方财富数据中心的请求限了并发和间隔。
- **看得见**。「设置 → 数据连接」最上面是一张表：每类数据的来源顺序、现在是正常、在用备用来源还是取不到，哪个来源从什么时候开始不通、报的什么错；点「现在查一遍」十来秒把每个来源问一遍。`wealthpilot doctor` 里是同一份。每个交易日的盯盘会顺带查一次，哪类数据彻底取不到了会写进当天的简报。

如实说明：

- 这只是让断线不那么疼，**不是把数据变可靠**。只有一个来源的还剩五类：分红、股东和机构持仓这种一个季度甚至一年才变一次的，把上一次取到的留满一个报告期，断线期间拿出来的多半就是最新的；一致预期和研报没有像样的替代来源，断了超过一个半月就是没有。
- 合规上的灰色只减轻了一点：LPR、社融、汇率用的是官方渠道，公告和两融有了官方的备用，其余仍然是东方财富、新浪、腾讯、百度的公开页面数据——只供个人研究，不要转发或批量下载。要有授权、有保障的数据，在「数据连接」里接自己的 iFinD、Tushare 这类账号。
- 主备切换、改版识别、用旧数据顶上这几条路径都有不联网的测试；每个来源本身用真实请求核对过一遍（2026-10-09）。它们明天还在不在，没有人能保证——所以才有每天那一次自查。

规划与进度见 [docs/stock-roadmap.md](stock-roadmap.md)。

## 自己干活：盯盘、模拟盘、财报正文、条件回测

**每日盯盘**。后端开着时，交易日到点（默认 15:30）自动跑一次，不调用模型：核对到期的验证点；检查持仓和自选里每只股票有没有新财报、重要公告（业绩预告、减持、回购、重组、问询等）、PE 分位跨档（低位 ≤20% / 高位 ≥80%）、大涨大跌；写成「今日简报」显示在首页。第一次见到一只股票只记基线，不把旧消息当新闻；同一件事不重复报。配置了 `ALERT_WEBHOOK_URL` 时有事才推送。也可以 `uv run wealthpilot watch` 手动跑或挂 cron。

**模拟盘**（`BROKER=paper`）。把"建议 → 授权 → 下单 → 成交 → 持仓"先在不动真钱的地方跑通：按最新价即时成交，买入整手、T+1、佣金万 2.5（最低 5 元）、卖出印花税万 5、资金不足拒单。下单只有两个入口——你授权一条建议单，或你自己在页面 / 终端下单；Agent 的工具里没有下单。成交后持仓自动同步进组合，只动由模拟盘同步来的记录，手工录入的（比如场外基金）不碰。**真实券商下单未接**：需要先选定券商再适配。

**财报与公告正文**。`read_latest_report` 定位最新一份定期报告里的管理层讨论、主营构成、业绩变动原因、风险、展望，摘原文片段给基本面 Agent；`read_announcement` 读任意一条公告的正文。文本接口只有"详见附件"时自动改读 PDF。正文是公司的自我陈述，提示词要求和财务数字对不上时指出来。

**选股条件回测**。`backtest_screen` 把一组筛选条件放回历史：每年 5、9、11 月初（财报披露截止日之后）按当时已披露的数据筛选——业绩按公告日判断，不用未来数据——等权持有到下一个调仓日，对比沪深300ETF。免费日线只能回溯约两年半，持有期只有六七个，结果偶然性很大；回测结果自带局限说明，Agent 引用时必须一并转述。

顺带修了一个筛选口径问题：报表里的 ROE 是累计值（中报 9% 相当于全年 18%），现在按报告期年化后再比较。

**行情源的备用**。日线主源（腾讯）对突发请求会临时限流；取不到时依次换东方财富（前复权）和新浪（不复权，返回里带 `price_basis` 标记）。

## 少记一点：只有五件事、名词解释、中文口令

功能多了之后，最大的成本是“我得先学会它”。这一节的东西都是为了把这个成本降下来。

**专业的叫法，配一句大白话**。界面上用的是行情软件和研报里通行的叫法——封板率、昨日涨停溢价、隐含增长率、超额收益、处置效应——这样你在别处看到同一个词时对得上、查得到。但不要求先学会：68 个术语各有一两句解释，是同一份：网页上每个页面底部（新加的几块是在内容下面）有一行“看不懂的词”，列着这一页用到的术语，点一下就地展开；左侧「设置 → 名词解释」是完整的一页，可以搜；终端里 `/glossary 封板率`；手机里发 `解释 封板率`。旧的口语叫法（追高、越跌越买、说话方式……）都能搜到对应的词条。

**不用记命令**。在终端和手机里，整句话正好是下面这些词就当命令执行，都不调用模型：`今日`、`市场`（或 `大盘`）、`持仓`、`自选`、`回顾`、`复盘`、`宏观`、`简报`、`对账`、`建议单`、`状态`、`用量`、`停`、`帮助`。只认“整句话正好是这个词”——“帮我复盘一下宁德时代上周为什么跌”仍然是一次研究。斜杠命令照旧可用；打错了（`/recpa`）会提示最接近的那一个。

**只有五件事**。0.11.0 之前左边栏有 25 个入口、今日页要翻六七屏、终端 `/help` 一次列出五十多个命令——功能是一个一个加上去的，是按“有什么功能”在摆，不是按“投资者要做什么”在组织。现在三个地方用同一套划分：今日、研究、市场、持仓、回顾。网页左边栏只有这五项（见上面[投研工作台](#投研工作台)）；终端 `/help` 默认只给这五件事各自最常用的一两个，十来行，`/help all` 才是全表；手机里发“帮助”也是这五行，“帮助 全部”是全表；`wealthpilot --help` 只讲怎么开始和这五件事，`wealthpilot help` 是全部子命令。今日页只留和你自己的股票有关的，大盘、行业、宏观搬去了「市场」。功能一个没删，只是不再都摆在第一层。

## 对照同类项目补上的：复盘、成绩单、估值、体检

调研了 GitHub 上高星的投研和金融 Agent 项目（TradingAgents、daily_stock_analysis、ai-hedge-fund、Vibe-Trading、FinRobot、ai-berkshire 等二十来个）之后补的。除了最后那个研究方法，这一节的东西都是取数之后的确定性计算，**不调用模型、不花钱**。

**每日大盘复盘**。每日简报只盯你自己的持仓和自选，这里讲的是市场本身：指数和涨跌家数，涨停、炸板、跌停和封板率，连板梯队，涨停集中在哪些题材（带同花顺整理的涨停原因），概念板块领涨领跌，龙虎榜上机构席位、北向席位和活跃营业部的净买卖。最后有一个“市场情绪”——冰点、偏冷、一般、偏热、高潮——是把五个公开数字套一把固定的尺子得出的，尺子写在 `services/recap.py` 的 `gauge()` 里，依据的数字一起给出来；它只是把“今天热不热”说成一句话，不是预测。看的地方：今日页的「大盘复盘」、`wealthpilot recap`、终端 `/recap`、手机里 `/recap`；每日简报推送时也会带上（`RECAP_PUSH=false` 关掉）。龙虎榜席位只按交易所披露的口径分类（机构、北向、个人、营业部），不去猜某个营业部背后是哪位游资。

**不开电脑也能每天收到日报**。电脑合盖，进程就停，这一点软件拦不住。借 GitHub Actions 绕过去：fork 这个仓库，在 Settings → Secrets and variables → Actions 里加 `STOCK_LIST`（你关注的股票，名称或代码，逗号分隔）和一个推送地址（`ALERT_WEBHOOK_URL` 群机器人，或 `TELEGRAM_BOT_TOKEN` 加 `TELEGRAM_CHAT_ID`），在 Actions 页面启用 `Daily brief` 工作流。之后每个交易日 18:00 它跑一份日报推到手机：大盘复盘，加上你点名的那几只今天的涨跌、有没有涨停及原因。不调用模型，GitHub 的免费额度够用；没配推送地址时这个任务直接跳过。它没有数据库，所以不知道你的持仓成本、验证点和建议单——那些仍然要在自己电脑上运行才有。如实说明：这个工作流的命令在本机用真实数据跑通过，但没有在 GitHub 上实际触发过一次定时任务。

**立场回溯**。验证点核对的是“我说的那个条件成立没有”，这里看更直接的一件事：立场本身对不对。每次给过立场（看多 / 中性 / 看空）的个股研究，从当天收盘价起，看 5、20、60 个交易日之后它比沪深 300 多涨还是少涨了多少。看多的要跑赢、看空的要跑输才算对，中性的要求差距在 5 个百分点以内。还没到日子的写“未到期”，已结算不到 10 条时明说样本太少。在「验证与回溯」页、终端 `/review`、手机 `/review` 里。只有打开个人模式之后的研究才写立场，所以没开过的话这里是空的。

**反向 DCF**。正着算 DCF 要先猜增长率，猜出来的“内在价值”很容易变成一个看着精确的目标价。反过来算老实得多：市值是已知的，问的是“利润要以多高的速度涨十年，折现回来才值这个市值”。个股页「估值」里的「隐含增长率（反向 DCF）」、终端 `/dcf 贵州茅台`、估值 Agent 的 `compute_reverse_dcf` 工具给出三档折现率下的隐含增速，旁边放着过去三年利润的实际增速，以及几档增长假设下“算出来的价值是市值的几倍”。口径都写在结果里：用的是近四个季度的归母净利润，没有扣资本开支，重资产公司会被高估；亏损公司算不了；金融类公司只作参考。Agent 的规则里写明了不得把它说成目标价或上涨空间。

**宏观数据**。制造业和非制造业 PMI、CPI、PPI、M1 / M2、新增人民币贷款、社会融资规模增量、GDP、LPR、中美国债收益率和利差，每项带最新值、上期值、所属月份和一句怎么读。今日页的「宏观」、`wealthpilot macro`、行业 Agent 的 `get_macro_indicators`。**没有社会融资规模**：试过的接口取不到，先用新增贷款和 M2 看信用松紧。

社会融资规模直接读中国人民银行官网的“社会融资规模增量统计表”（东方财富的数据中心没有这一项），和别的月度数据同步更新。央行的页面打不开时退到商务部商务数据中心的转载——那个转载更新得慢，2026 年 10 月时只到 4 月；退到它而且晚了两个月以上时，这一项会用黄字写明“只更新到哪个月”，Agent 拿到的数据里也带着这句话。

**题材和产业链**。两个新工具：`get_concept_boards` 看概念板块今天的强弱，`get_concept_stocks` 拿一个板块里的公司。研究方法库里多了一个「题材产业链拆解」（`wealthpilot skills install theme-chain`）：把一个题材从下游往上游拆开，找最难替代的环节，再用主营构成核对板块里的公司是真受益还是沾边。这个方法会调用模型，和一次普通研究的花费相当。

**交易行为诊断**。研究写得再好，钱是在买卖的那一下亏掉的。把券商导出的交割单贴进「交易行为诊断」页（或 `wealthpilot trades 交割单.csv`），它按先进先出把买卖配成一笔一笔的来回，然后数：有多少次是在大涨之后才买的、交易得勤不勤、有几次是越跌越买、赚钱的单子和亏钱的单子各拿了多久、胜率和盈亏比、卖出之后又怎么走。占比够高的才标成“留意”，每一条都带数字和例子。它只看行为，不评价你选的股票；成交记录只在这次计算里用，不存进数据库。

**买入理由记录，按来源对账**。很多买入不是研究出来的：看到一位博主的帖子、朋友提了一句、群里在传。这没什么，但值得记下来。每次动手记一句——为什么买，消息从哪来（自己研究、AI 研究、博主 / 大V、朋友推荐、新闻 / 公告、群 / 论坛、券商研报）：网页「交易行为诊断」页填表，终端 `/why 宁德时代 储能订单超预期 来自 雪球某某`，手机里发“记一笔 宁德时代 储能订单超预期 来自 朋友”。过一阵子发“对账”：每一类来源各买了几笔、买入之后 20 和 60 个交易日有几笔跑赢沪深 300、平均超额多少；同一个人推过两笔以上的会单独列出来。用的是和立场回溯同一把尺子，全部由行情算出来，不调用模型，也不评价谁——只把结果摆出来。到期的不满十笔会提醒样本太少；港股、美股也是和沪深 300 比的，只能看个大概。

**研究带得走**。研究页和研究记录里，每一次回答下面有「存成 Markdown」和「打印 / 存成 PDF」：前者和终端 `/export` 存出来的是同一种文件（问题、回答、证据清单），后者在新窗口里排成一页干净的文档，打印对话框里选“存储为 PDF”就是 PDF。都在浏览器里完成，不经过服务器。

**通用技能包**。ai-berkshire、investorskills、serenity-skill 这些热门的方法论都是 SKILL.md 格式。现在 `wealthpilot skills install https://github.com/…` 认得它：仓库首页或目录地址都行。导入时去掉代码块（那些脚本在这里跑不了），补上派哪几个 Agent、报告分哪几节的默认值，太长就截断并说明——保留下来的是“怎么判断”的那部分。装之前会把改写后的全文给你看。

## 像个成熟的 Agent：换模型、管花费、断了能接上

对照 OpenClaw、Hermes 这类通用 Agent，这里补的是几件"用着才发现缺"的事。这一轮的改动全部用假模型离线验证，没有调用真实模型。

**接什么模型都行**。除了 DeepSeek 和 Claude，「设置 → 模型」里多了第三种：任何兼容 OpenAI 接口的服务。填接口地址、模型名、Key 就能用；硅基流动、智谱、Moonshot、阿里云百炼、火山方舟、OpenRouter、OpenAI 和本机 Ollama 的地址可以一键填好。本机模型不需要 Key。两个前提要如实说：模型必须支持工具调用，否则 Agent 取不了数；这些服务没有逐个实测过，小模型的工具调用和中文长文质量通常明显差一截，填好后先点「测试当前配置」。

**主模型用不了时不白等**。可以再设一个备用模型（`wealthpilot model fallback ollama`，或网页「设置 → 模型 → 备用模型」）。研究途中主模型报余额不足、Key 失效、被限流、连不上时，这一轮自动换到备用模型接着跑，回答上会写明"这一轮是备用模型答的"，而不是六个 Agent 各撞一次墙然后整轮作废。模型分三个位置——DeepSeek、Claude、兼容服务（其余几家和本机模型共用这一个）——各存一套 Key 和模型名，主模型和备用模型各占一个，所以最省钱的搭配是"DeepSeek 为主，本机 Ollama 兜底"。限流、超时这类一时的问题先自动重试（默认 3 次，按服务商给的等待时间退避，`wealthpilot config set ai_max_retries 5` 可调），重试完还不行才换。一轮里换过去就不再回头试主模型。已经开始出字之后才断的流不接管，那一步照常报错。

**出了事有地方查**。研究在后台跑挂了、推送没发出去、盯盘那一次出了错、模型换了路，以前都只是被悄悄兜住。现在都写进数据目录下的 `logs/wealthpilot.log`（单个 1 MB，留最近 3 份），`wealthpilot logs --errors` 直接看出问题的那几条，自检里也多了一项"最近 24 小时有没有警告和错误"。每次研究结束记一行：状态、用时、token、类型，提问只记开头三十个字。写进文件之前会把长得像 Key 和令牌的字符串抹掉；日志只在你自己的机器上，不上传。

**数据带得走**。`wealthpilot backup` 把数据库、配置、你写的研究方法、数据连接打成一个文件——数据库用的是 SQLite 自己的在线备份，WealthPilot 开着也能打。默认带着 Key（文件只有你能读，换电脑不用重填），`--no-keys` 去掉后可以放网盘。`wealthpilot restore` 放回来之前先把现状自动备份一份，恢复错了能回头；备份里没带 Key 时保留这台机器上的 Key；不是自己打出来的压缩包、里面有想写到数据目录外面的路径，一律拒绝并且什么都不动。

**回答风格你说了算**。在数据目录下放一个 `SOUL.md`（名字沿用 OpenClaw、Hermes 的叫法），写一段话告诉它怎么跟你说话：`wealthpilot persona use friend` 直接用现成的“懂行的朋友”，另外三个是“只要要点”“讲给新手”“多泼冷水”；也可以 `wealthpilot persona set "先说结论，用大白话，别用套话"`，或在网页「设置 → 回答风格」里改。这段话会写进每个 Agent 和最后执笔那一步的系统提示里，并且明说“与规则冲突时以规则为准”——它管的是语气、措辞和详略，证据引用、数字核对、必须有的章节和风险提示不会因为一句“说短点”被省掉。没写的时候系统提示和以前逐字相同。如实说明：这是一个机制，离线测过的是“这段话确实到了模型手里、规则在它前面”；换了回答风格之后真实模型写出来到底像不像人话，没有拿真实模型跑过。

**固定数据源之外的事，它会自己去搜**。行业与市场、预期与消息这两个 Agent 多了 `web_search` 和 `read_webpage`：公司最近的事件、订单、政策原文、网上流传的某个说法，财报和行情接口里查不到的，它自己搜、挑一两条读原文。默认不用 Key（直接读搜索引擎的结果页），不花钱，但对方随时可能改版或拦截，搜不到时它如实说没搜到；想稳定可以接博查、Tavily、Brave 或自己搭的 SearXNG（`wealthpilot config set web_search bocha` 再 `config set web_search_api_key …`），不想要就 `config set web_search off`。几条界线：网页是没核实过的东西，结果里带着提醒，回答里引用网页要写明来源网站和日期；财务数字、估值、行情仍然只从专门的工具取；读网页只走公网的 http / https，本机、内网、链路本地地址一律拒绝，跳转的每一跳都重新检查，免得一个恶意链接让它读到你电脑上的服务。如实说明：不用 Key 的搜索在本机实际搜过、读过网页；带 Key 的四家是照文档写的，用模拟接口测的，没有真的调过。

**钱花在哪、能不能少花**：

- 「设置 → 用量与预算」能看到今天、近 7 天、近 30 天各用了多少 token、花在哪类问题上；填了你那家的单价会折成钱（按输入全价算，是个上限）。开跑前，等待卡片上会写这类研究最近平均花多少。
- 可以设每日 token 上限，到了就不再调用模型，第二天自动恢复。
- 同一个会话里的后续问题，以前会把之前的完整回答（每篇五六千字）原样发给每一个 Agent、每一轮工具调用再发一遍；现在只带问题和回答的结论。会话越长省得越多。
- 几小时内（默认 4 小时，可改）再对同一只股票做深度研究：问题一模一样就把上一次的结果原样给出来，不花 token；问法不同就只用那批证据重写一遍。页面上会明确写"这次没有重新取数"，旁边有「重新取数研究」；选「深入」档则总是重新取。
- 多空辩论可以在设置里关掉（每次省两次调用）。

**模型用不了时说人话**。余额不足、Key 失效、模型名不对、被限流、连不上——认出来之后整轮研究立刻停，不再让六个 Agent 各报一串英文错误再走完审核和重写；页面上是一句话加一个去设置的入口。

**研究不绑在网页连接上**。以前关掉标签页或刷新，跑到一半的研究就被取消，token 花了、结果没存。现在研究在服务端独立运行：页面断开不影响它跑完并存进研究记录；刷新后会自动接回正在跑的那一次；会话存在浏览器本地，刷新不丢。只有点「停止」才会真的取消。（任务只活在这个进程里，进程退出就没了——不做后台常驻。）

**从自己的对错里学一点**。每类判断（财务、估值、涨跌）事后核对下来的成立率，会带进新一轮研究：某一类经常落空，下次同类判断就要更保守。样本不到 5 条的类型不提。这是按成绩单做的校准，不是模型自己"悟"出来的。

**推送**。群机器人的 webhook 以前发的是一种"都带上"的格式，飞书和 Slack 其实不认；现在按地址认出是飞书、企业微信、钉钉、Slack 还是 Discord，各发它认的格式，并读取对方返回的错误码。定时任务的结论和提醒以前只推 Telegram，现在所有渠道都推。钉钉机器人如果设了关键词或加签，需要在机器人那边放行。这些格式是照各家文档写的，用模拟的接口测过，没有对着真实的群机器人发过。

**会话找得回来**。研究页空着的时候会列出最近的会话，对话中右上角有「历史会话」；点一个就回到当时的对话，每一轮的证据、校验结果、验证点都在，可以接着问或换个写法。定时任务和手机上发起的会话也在列表里，标了来源。终端里是 `/sessions`。

**记经验、提议方法**（都尽量不花钱）：

- 一条验证点被证伪时，程序照实记一条经验——当时认为会怎样、实际是多少、当时的理由——之后再研究这只股票会带上。这一步不调用模型。
- 已核对的判断攒够 4 条后，「验证与回溯」页可以点「让它归纳规律」：把这些记录交给模型找跨股票的规律，一次调用。每条规律必须有至少两条记录支撑才会收下，收下的可以删。
- 同一种问法问过三次、涉及两只以上的股票（比如“××的分红能不能持续”），「研究方法」页会提议把它存成方法。发现是代码做的；点「起草成方法」才调用模型，写出来先给你看，你点保存才生效。只是“帮我分析一下××”这种通用问法不会被当成方法。

和 Hermes 那种“自己学会新技能”相比，这里保守得多：它只会记录、归纳和提议，不会在你不知道的情况下改自己的做法。

和成熟的通用 Agent 相比，还没有的：浏览器操作之类的通用工具（不打算做，这是个投研工具）；飞书、企业微信的卡片按钮；企业微信在没有公网地址时的接入。

## 基础的东西：数据、分工、辩论、图表

行情软件有的基础数据和图，这里也要有，而且 Agent 要用得上。这一轮补的就是这些。

**数据源**（都是实测能取到的公开接口，取不到时如实返回"未获取到"）：

| 类别 | 内容 | 来源 |
|---|---|---|
| 资金 | 逐日资金净流入、按单子大小拆分、主力成本 | 新浪资金流向、东方财富数据中心 |
| 杠杆 | 融资余额、融资买入、融券余额（逐日） | 东方财富数据中心 |
| 筹码 | 股东户数与户均持股、十大流通股东、各类机构持仓、北向持股 | 东方财富数据中心 |
| 内部人 | 股东与董监高增减持、回购、限售解禁、大宗交易、龙虎榜 | 东方财富数据中心 |
| 预期 | 卖方一致预期（评级分布、EPS 预测、目标价区间）、研报列表、业绩预告与快报 | 东方财富数据中心、研报接口 |
| 消息 | 个股新闻（标题、摘要、媒体）、机构调研纪要 | 东方财富 |
| 经营 | 主营构成：按产品、地区、行业的收入占比与毛利率 | 东方财富数据中心 |
| 行情 | 分时、五日分时 | 腾讯行情 |

**两个新的研究维度**。个股深度研究从四个维度变成六个：新增「资金与筹码」（最近是谁在买谁在卖、票在谁手里、后面有没有抛压）和「预期与消息」（券商原本以为它会怎样、公司自己怎么说、最近有什么新闻）。有了一致预期，报告才分得清"业绩好"和"业绩好于预期"。

**多空辩论**。写报告之前，先让看多、看空两方就同一批证据各打各的：每方最多三条理由，一句大白话，必须挂证据编号，里面的数字过和正文一样的溯源检查，对不上的整条丢掉；各自还要认一条软肋。撰写环节必须判哪一方的证据更站得住，不许各打五十大板。页面上是左右两栏的卡片，点理由后面的编号能看它依据的数据。

**图表**（个股页）：

- 走势：分时、五日分时（昨收参考线、均价线、成交量）；K 线加了 MA60 和可选的 MACD
- 财务：单季营收与净利润柱状图（由累计值相减得到）、主营构成环图与各业务毛利率
- 资金与筹码：每日净流入叠在股价上、融资余额叠在股价上、股东户数叠在股价上，十大流通股东、机构持仓，以及增减持 / 回购 / 解禁 / 大宗 / 龙虎榜的时间线
- 预期与消息：评级分布、券商目标价区间和现价的位置、EPS 实际与预测、研报、业绩预告、新闻、调研

**顺带把研究做稳了**。维度多了以后暴露出几处会让研究白等一分钟却被校验拦下的问题，一并修了：固定模板的证据够不够改由代码按"哪个工具取到了数据"判定；"没做风险测评却写了具体仓位"改为只改那一处而不是整篇重写；抄错一位的证据编号由代码补全；"基金减仓 33%"这类别人的动作不再被当成给用户的建议。实测贵州茅台、宁德时代、招商银行、软通动力四只：六个维度加辩论 37 到 44 秒，全部通过校验（改之前同样的问题要 54 到 71 秒，并且有被拦下的情况）。

几点如实说明：

- **更费 token**。一次个股深度研究的输入从约 8 万涨到 15 到 19 万 token。「快速」档不受影响。
- **资金流向是估算**。它按每笔成交的方向推断"主动买入还是主动卖出"，不等于机构真的在买；新浪和东方财富的口径不同，页面和报告里分开标注，不混着算。
- **一致预期偏乐观**。卖方很少给"卖出"，覆盖机构少的公司样本很薄。工具返回和报告里都会带上覆盖机构数，并写明目标价是"券商给出的"。
- **机构持仓、股东户数滞后**。来自定期报告，晚 1 到 3 个月；北向持股 2024 年 8 月起只按季度披露。
- **免费接口没有保证**。这些都是公开网页用的接口，没有服务承诺，哪天改了字段就会取不到；`wealthpilot doctor` 会逐类探测，告诉你现在哪一类不通。
- **第一稿常有几个自己算出来的数**（比如用现价除以某年 EPS）。它们过不了溯源检查，会被定点修订删掉，所以报告里偶尔能看到一句话少了个具体数字。

## 对话：等待、结论、快速与改写

一次完整研究要四五十秒，回答动辄几千字。这一组改动是为了让这两件事不那么难受：

- **等的时候知道在干什么**。研究一开始就给出预计用时（取同类研究最近几次的实际耗时），页面上是进度条、倒计时和五个阶段（规划 → 取证 → 审核证据 → 写结论 → 核对），取证阶段写明哪几个维度还在跑。可以切到别的页面；跑完时如果你不在这个标签页，标题会变，允许过通知的话还会弹一条系统通知。
- **先给结论**。长报告跑完先显示一张结论卡片——几句话加立场（看多 / 中性 / 看空）——完整报告折叠在下面，展开一次就记住你的选择。终端里则是在全文之后再把结论放一遍，停下来时眼前就是它。
- **快速 / 深入**。输入框下面三档：自动、快速（只派一两个 Agent，十几秒，简短，不留验证点）、深入（完整研究）。终端里是 `/quick <问题>`、`/deep <问题>`、`/depth`。
- **换个写法不用重新研究**。回答下面的「更短一点 / 只讲风险 / 换成给新手的说法 / 列成要点」，或勾上「只用上一轮的证据回答」再追问，都只用那一轮已经取到的证据重写：实测 3 到 8 秒，同样要过数字溯源校验；证据里没有的东西它会直说"需要重新研究"，不会现编。终端里是 `/rewrite <要求>`，`/history <编号>` 可以调出以前的某一次接着改写或追问。

## 手机渠道（Telegram、飞书、钉钉、企业微信）

四个渠道接一个就行，在网页版「设置 → 手机渠道」里配，或者不开网页、在终端里用 `wealthpilot channels`（看卡在哪一步、配置、出配对码、发测试消息）。它们共用同一套逻辑：能收什么、能问什么、怎么处理建议单都一样，区别只在怎么接上。

| 渠道 | 怎么收消息 | 需要公网地址吗 | 接入要做的事 |
|---|---|---|---|
| Telegram | 长轮询 | 不需要（但本机要能访问 Telegram，可以填中转地址） | 找 @BotFather 建机器人，填令牌 |
| 飞书 | 官方 SDK 的长连接 | 不需要 | 开放平台建企业自建应用：加机器人能力，开通收发消息权限，事件订阅选「使用长连接接收事件」并添加「接收消息」，发布；填 App ID 和 App Secret，**重启 WealthPilot** |
| 钉钉 | 官方 SDK 的长连接（Stream 模式） | 不需要 | 开放平台建企业内部应用：加机器人能力，消息接收模式选 Stream，开通「企业内机器人发送消息」，发布；填 Client ID 和 Client Secret，重启 WealthPilot。只认单聊，群里 @ 它没有回应 |
| 企业微信 | 回调（它来调你） | **需要** | 管理后台建自建应用，「接收消息」的 URL 填 `https://你的地址/api/channel/wecom/callback`，填企业 ID、AgentId、Secret、Token、EncodingAESKey；把服务器 IP 加进「企业可信 IP」 |

绑定都是同一个办法：设置页生成配对码，在那个应用里给机器人发 `/pair 123456`，发对了它就认这个聊天做主人，别人发消息不会有回应。飞书和企业微信的文字消息没有按钮，授权建议单时按提示回复命令（`/ap 3` 发起、`/ok 3` 确认、`/no 3` 取消、`/rj 3` 不采纳），同样是两步。

企业微信那条限制是它的机制决定的：自建应用只能靠回调收消息，所以只在自己电脑上跑、没有公网地址时用不了，请用飞书或 Telegram。回调接口不要求登录（企业微信的服务器要能调），靠签名校验和 AES 解密把关，验不过一律拒绝。

如实说明：飞书和企业微信这两个渠道是照官方文档和飞书 SDK 写的，测试用的是模拟接口——飞书的事件对象是拿 SDK 自己的模型造的，企业微信的加解密做了往返测试——**没有用真实的应用跑过**，Telegram 同样如此。接的时候卡在哪一步，`wealthpilot doctor` 会报出飞书长连接的错误。

下面以 Telegram 为例：

电脑不在手边时也能收到它、指挥它。在 Telegram 里找 @BotFather 建一个机器人（发 `/newbot`），把令牌填进网页版「设置 → 手机渠道」并保存，再点「生成配对码」，把页面上那条 `/pair 123456` 发给你的机器人——发对了它就认你这个聊天为主人，之后别人给它发消息不会有回应。

- **收**：每日简报（有事才推）、定时任务的结论、提醒。
- **问**：直接发问题就是一次研究，回来的是结论卡片；`/quick` 快速回答，`/deep` 强制重新取数，`/rewrite 更短一点` 用上一个回答的证据换个写法。
- **管**：一次只查一个——手一快连发两条，第二条会被告知上一个还在查，不会同时跑两次、花两份钱；`/stop` 停掉正在查的（已经花掉的 token 照常记账）。`/status` 看模型、今天用量、正在查什么，`/usage` 看用了多少。
- **发图、发语音**：截一张别人的观点、持仓或图表发过来，它先把图里的内容转成文字给你看一眼认得对不对，再照着查；图上附一句话（“这个说法靠谱吗”）就直接开查，没附就等你下一句。语音也一样，先回“听到的是……”。语音只当提问，听成了命令也不执行——授权建议单必须打字。看图要一个能看图的模型（`wealthpilot config set vision_model glm-4v-flash`，或填了 Claude 的 Key），语音要一个转写服务（`stt_base_url` / `stt_model` / `stt_api_key`）；钉钉的语音它自己识别好了，不用配。没配的时候它会直接告诉你怎么配。企业微信这边暂时只收文字。
- **看**：`/stock 茅台` 行情与估值分位，`/holdings` 持仓和浮动盈亏，`/watch` 自选，`/tasks` 定时任务和提醒，`/digest`、`/review` 简报和成绩单。
- **处理建议单**：`/proposals` 列出来，每条带「授权 / 不采纳」按钮。授权要点两次（第二次是确认），执行的仍然是你在电脑上会走的那条路径：开了模拟盘就在模拟盘成交，否则只记账。

机器人跟着 WealthPilot 的进程长轮询，不需要公网地址；本机到不了 `api.telegram.org` 时可以在同一处填中转地址。配对码只能在运行后端的那台机器上生成，10 分钟有效。

如实说明：这部分是对着 Telegram Bot API 的文档写的，测试用的是模拟出来的接口（配对、命令、按钮回调、非主人消息被忽略都有覆盖），**还没有连真实的机器人跑过**。

## 自动任务：到点自己研究、到价提醒

「自动任务」页（终端：`/tasks`、`/alert`）。

**定时任务**——到点自己做一次研究，结论记进当日简报，绑定了手机就同时推过去：

```
工作日 08:30   帮我诊断一下我的持仓，有什么需要注意的
每周五 16:00   复盘一下之前的研究：验证点成立了多少，哪些判断被证伪了
每周一 09:00   帮我筛选市盈率低于15、ROE高于15%的大市值股票
```

时间直接用中文写（`每天 08:30`、`工作日 15:40`、`每周一三五 9点半`），输入时当场显示它读成了什么。每个任务可以选查多深，也可以点「现在跑一次」先看效果。

**提醒**——某只股票的价格、当日涨跌幅、PE / PB 历史分位越过你设的条件时说一声，比如"贵州茅台跌到 1350 元以下""宁德时代 PE 分位低于 20%"。由代码取数判定，不调用模型；建好当场告诉你现在是多少。默认触发一次就停，免得在阈值附近来回提醒；也可以选每天最多提醒一次。取不到数就不判，不会拿默认值去触发。

几条边界：

- **不常驻后台**。和每日盯盘一样跟着 WealthPilot 的进程跑，不装系统服务。电脑合着盖错过了时间，下次打开时补跑最近错过的那一次（36 小时以内）；再久就等下一次。要全天候，放到一台不休眠的机器上（见 Docker 部署）。
- **有上限**。定时任务会调用模型，每天最多自动跑 6 次（`AUTO_DAILY_RUNS_MAX`，设置页可改），超了的那次记为"跳过"并写明原因；手动点的不算。
- **只研究，不下单**。任务跑出来的建议单和平时一样，等你逐条授权。
- 每次运行和触发都进审计日志。

## 可调教、可追责：研究方法、记忆、审计、用量

这一组能力参考了 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（`dsh`）的几个约定：技能文件格式、审批结果的取值、`domain/action` 式的事件命名、保持模型可见前缀稳定以命中上下文缓存。编排器本身没有迁过去——它是 Node.js 的通用运行时且仍在开发者预览，而这里的证据链、Critic 和验证点正是编排器里的东西。

### 研究方法（技能）

把你自己的方法写成一个 Markdown 文件教给 Agent。话里出现触发词或方法名，就按它来研究，不再让模型另行规划。

```markdown
---
name: dividend-check
description: 高股息检查——这只股票的分红能不能持续，现在的股息率值不值得拿
whenToUse: 用户关心分红、股息率、收息、红利股的时候
metadata:
  wealthpilot:
    label: 高股息检查
    triggers: [高股息, 股息率, 分红能持续, 红利股]
    needs: stock                       # stock / stocks / holdings / none
    agents: [fundamental, valuation]   # 派哪几个 Agent 并行去查
    sections: [结论, 分红记录, 分红能力, 估值, 风险]
    criteria: [最近几年的分红方案与股息率, 净利润、经营现金流与资产负债率]
---
- fundamental: 查分红记录和多期财务指标。分红是不是连续的、每股经营现金流能不能覆盖每股分红……
- valuation: 股息率高有两种来历：分红多，或者股价跌得多。结合 PE / PB 分位说清楚是哪一种。
```

- 文件放在 `backend/skills/`（或 `~/.wealthpilot/skills/`），`<name>.md` 或 `<name>/SKILL.md`，改完立即生效。自带两个示例：高股息检查、财报季检查。
- 格式与 dsh 的 skill 相同（必填 `name` / `description`，可选 `whenToUse`），同一个文件在 dsh 里也能当普通技能加载；编排信息放在 `metadata.wealthpilot` 下。
- 正文里 `- <agent>: ……` 这一行就是给那个 Agent 的具体做法；整篇正文会交给撰写环节。报告章节由 Critic 检查，缺了会打回。
- 工作台「研究方法」页可以直接新建和编辑；不合格的文件不会保存，会用人话说明哪里不对。技能研究同样留验证点。

不用从空白文件写起，方法有三个来源（网页「研究方法 → 添加方法」，终端 `/skills gallery | install | draft`）：

- **现成的**：仓库自带六个（`backend/skills-gallery/`）——低估值陷阱检查、银行股体检、成长质量检查、买入前检查清单、持仓风险排查、行业扫描。点一下就复制进你的技能目录，之后是你自己的文件，随便改。
- **让 AI 起草**：说一句"我买消费股之前固定看提价能力、渠道库存、估值分位"，模型按这里的格式写出完整文件（实测 4 秒左右）。起草结果同样过校验，不合格会把问题退回让它重写一次；仍不合格就连同问题一起给你看，不假装成功。
- **从链接导入**：别人分享的 `.md`，支持 GitHub 文件地址。只允许 https、有大小上限。

后两种都**只取回、不直接保存**：方法文件是写给 Agent 的指示，会决定它以后怎么研究，所以先放进编辑器给你看过，你点了保存才生效。

### 投资者记忆

你说过的偏好和纪律（“我只做长线”“单只股票不超过两成仓位”“我不碰……”），和你对建议做过的决定（采纳了什么、没采纳什么、为什么），与对话记录分开存，每一轮研究都带上；结论与其中某条冲突时 Agent 必须明说。

- **只记你的原话**：命中“记住”“我不碰”“我只做”“单只不超过”这类说法的句子才记，不让模型替你总结偏好。
- 不采纳一条建议时可以写原因，原因会记下来；针对某只股票的决定只在研究那只股票时带上。
- 工作台「AI 记住的事」页、终端 `/memory` 可以查看、添加、删除。

### 审计日志

AI 提过什么建议、你怎么决定的、下过哪些单、同步过什么持仓、改过哪些配置，全部只追加、不修改。每条带上一条的哈希，事后改动或删掉任何一条，校验都会对不上（`GET /api/audit` 每次返回校验结果）。

事件名沿用 dsh 会话日志的 `domain/action` 约定：`research/published`、`checkpoint/created`、`checkpoint/verified`、`approval/asked`、`approval/decided`（结果为 `allowed-once` 或 `rejected`，与 dsh 审批子系统一致）、`order/filled`、`order/rejected`、`holdings/synced`、`settings/changed`（只记改了哪些项，不记值）、`memory/added`。

### 用量、缓存与证据外置

每轮研究结束时给出这一轮的模型用量：调用次数、输入与输出 token、其中多少输入命中了上下文缓存（工作台和终端的状态行里都能看到）。

一轮研究里，同一批证据要发给审核、撰写，每次打回重写还要再发一遍。量下来，一次深度研究的原始证据约 2.7 万字，财报正文摘录一项就占四成。所以做了三件事：

- **证据外置**：完整证据留在证据库，数字溯源校验和界面上的“查看证据”用的仍是全文；交给审核和撰写环节的是压缩版——长列表只留前几项、长文只留开头、不再每条附一整段元数据。撰写要用的数字，取证的 Agent 已经在初步结论里带着证据 ID 引用过了。
- **定点修订**：校验没过、且问题只是个别数字对不上时，不重发证据、不重写全文，而是让模型给出几处“原文片段 → 改后片段”，由代码套上去；套不上就退回完整重写。
- **兜底删句**：重写和修订都去不掉的数字，把含它的那半句话删掉（表格里换成“—”）再核对一次，过了就标注为部分发布——不因为一两个数字把整篇核对过的内容扣下。

同一套 12 题、同一个模型（DeepSeek，个人模式开启），改动前后各跑一次：

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 通过校验 | 8 | 11 |
| 带标注发布 | 4 | 1 |
| 未发布 | 0 | 0 |
| 平均耗时 | 37.0 秒 | 26.9 秒 |
| 平均输入 token | 73,156 | 38,405 |
| 其中未命中缓存的输入 | 38,916 | 25,307 |
| 平均输出 token | 10,298 | 7,834 |
| 平均被打回次数 | 1.5 | 1.08 |

各跑一次、12 题，模型输出有随机性：方向可信（改动后另跑过一次，输入 37,677、耗时 27.7 秒，结果接近），具体幅度不要当精确值。回答平均字数基本没变（4,017 → 3,937）。

另外：各 Agent 的系统提示和工具定义逐字不变，会变的内容（持仓快照、解析结果、记忆、旧验证点）放进用户消息，以命中上下文缓存；`LIGHT_MODEL` 可以让提取证券名、审核证据、提出验证点这些轻活用另一个模型（默认与主模型相同，换模型后的质量没有实测过）；只要 JSON 的调用在 DeepSeek 上使用 JSON 输出模式。

## 事后验证与复盘

多数分析工具停在"写出一篇看起来靠谱的分析"，没人回头检查当时说得对不对。WealthPilot 把这件事做成闭环：

```
研究发布 ──► 提出验证点 ──► 到期核对 ──► 成绩单 ──► 带进下一次研究
            模型提、代码校验   代码取数判定   成立率      被证伪的旧判断必须正面回应
```

1. **提出**：回答通过校验并发布后，多一次小额模型调用，把结论最依赖的 2–3 条判断写成"指标 + 条件 + 时点"。代码逐条校验：指标必须在白名单里、代码必须是本次研究的股票、基准值由代码当场取到，否则丢弃。
2. **核对**：财务类（营收同比、净利同比、毛利率、净利率、负债率）等**紧接着的下一期财报**；估值类（PE / PB 历史分位）在到期日核对。判定是纯代码，模型不参与。
3. **成绩单**：成立率 = 成立 /（成立 + 证伪）。已核对出结果的验证点不能删除，成绩单不会因为删掉证伪的条目而变好看。
4. **带回**：再次研究同一只股票时，此前的验证点及结果会交给 Agent，被证伪的必须说明原判断错在哪、结论是否因此改变。
5. **复盘**：问"复盘一下之前的研究"会交给复盘 Agent，它只用成绩单和验证点两个工具作答，样本不足 10 条时必须明说不具统计意义。

如实说明：验证点只覆盖代码能核对的几类指标，定性判断（管理层、竞争格局）不在其中；刚做完的研究验证点都是"待核对"，成立率要等财报和到期日过去才有。

### 个人模式：立场、操作建议与授权

默认情况下 Agent 只陈述事实与推断，不给目标价和买卖建议。这是个人自用的工具，可以打开个人模式：

```bash
# backend/.env
ADVICE_MODE=true
```

打开后：

- 个股研究多一节「建议」：立场（看多 / 中性 / 看空）、对应操作、**失效条件**（缺了会被 Critic 打回）。"必涨""稳赚""保证收益"这类承诺任何模式下都不允许。
- 给出看多 / 看空立场时，自动加一条**涨跌类验证点**：到期日核对相对沪深300ETF 的超额收益，事后给这次判断打分。
- 回答里有明确的买入 / 加仓 / 减仓 / 卖出建议时，生成一张**操作建议单**。Agent 只能提出；每一条都要你自己授权。
- 授权 = 把成交的数量和价格记入持仓台账（工作台「验证与回溯」页，或终端 `/approve`）。**不会向券商下单**：你在自己的券商成交后把结果填回来。外部连接器里的交易类工具仍然是屏蔽的。
- 仓位与数量仍受风险画像约束；没做风险测评时只给方向，不给比例和数量。

## 接入券商与金融数据服务（MCP）

妙想、iFinD、Tushare 这类数据服务可以接进来，它们的工具会和内置的 59 个一起交给 Agent 用。不接也能用，接了多的是它们各自的独家数据。

```bash
wealthpilot connectors gallery                       # 现成的有哪些：是官方的还是社区的、要什么、接不接得上
wealthpilot connectors add mx                        # 接妙想（社区封装，先在本机把它跑起来）
wealthpilot connectors add ifind --url <地址> --token <密钥>
wealthpilot connectors test mx                       # 连一次：哪些工具可用、哪些被屏蔽
wealthpilot connectors remove mx
```

| 服务 | 出处 | 现在能不能接 | 要什么 |
|---|---|---|---|
| 东方财富妙想 | 社区封装（东方财富没有公开的官方 MCP 地址） | 能 | 妙想的 MX_APIKEY；在本机跑社区项目 [eastmoney-skills2mcp](https://github.com/essos-bot/eastmoney-skills2mcp) |
| 同花顺 iFinD | 官方（2026 年 3 月发布） | 能，要你提供地址 | iFinD 终端账号，在终端里拿服务地址和专属配置密钥 |
| Tushare | 社区封装 | 能，要你提供地址 | Tushare token，自己跑一个社区的 Tushare MCP 服务 |
| 长桥 Longbridge | 官方 | **不能** | 它只认浏览器登录授权（OAuth），这里的连接器只会带一个固定令牌 |
| 别的 | — | 能 | 任何提供 HTTP 接入的 MCP 服务的地址，要鉴权再给令牌 |

如实说明：这张表是查公开资料整理的，**没有一家实际连过**——都要账号或 Key，手上没有。连接器本身（列工具、调工具、屏蔽写操作、带令牌）是用项目自己的 MCP Server 当外部服务测通的；对着这几家真实服务会不会有出入，要有账号的人试了才知道。

- **只读，硬性屏蔽会动账户的操作**：名字或说明像下单、撤单、转账、申赎、增删改自选的工具一律不暴露给 Agent，也不能通过本服务调用，配置里的白名单也绕不过。WealthPilot 只做研究与分析，不代你交易。
- **令牌不进配置文件**：`--token` 给的令牌存进你数据目录下的 `.env`，`connectors.json` 里只有环境变量的名字；接口返回里不会出现令牌或启动命令。
- **只在本机的命令行里接**：没有“通过网页新增连接器”的接口——那等于让服务器替网页用户访问任意地址或执行命令。网页的「数据连接」页只负责看清单和测试连通。
- **照常进证据链**：外部工具的返回和内置工具一样生成证据 ID，接受 Critic 的数字溯源。
- 支持 HTTP（Streamable HTTP）和 stdio 两种传输。想手写配置：数据目录下的 `connectors.json`，模板是 `backend/connectors.example.json`，里面带一个 `wealthpilot_self` 示例（把本项目自己的 MCP Server 当外部服务接进来，用来验证链路）。

### 升级

```bash
wealthpilot update
```

一条命令装的和从源码装的都这样升级（前者的代码目录 `~/.wealthpilot/app` 本身就是一份仓库）；重新运行一次安装脚本效果相同。

它做的事：检查远端有没有新提交 → **备份数据库**到 `data/backups/`（留最近 5 份）→ `git pull --ff-only` → 装依赖 → 重新构建网页版 → 打印这次更新了什么（取自 [CHANGELOG.md](CHANGELOG.md)）。数据库里新增的字段在下次启动时自动补上。

它不会做的事：仓库里有你没提交的改动、或者不在 `main` 分支时，它会停下来说明情况，不拉取、不覆盖；任何一步失败都如实报出来并告诉你怎么补（`make setup`）。

有没有新版本不用自己记着查：后端启动后在后台看一眼远端（只读取本仓库的远端，不上传任何东西），有的话在终端问候语、网页首页和「设置 → 版本与自检」里提示。不想要可以在设置里关掉「启动时检查更新」。Docker 部署的升级见 Deployment 一节。

如实说明：检查更新、拒绝覆盖本地改动、已是最新、数据库备份这几条路径都有测试；“装好 → 远端多出一个提交 → `wealthpilot update` 备份、拉取、装依赖、重建网页 → 再跑一次显示已是最新”这条完整路径，在本机用一份仓库副本当远端实际跑通过（用安装脚本装出来的那种目录），升级后代码目录是干净的。没有验证过的是：从 GitHub 上真实拉取（网络慢或断开时的表现只有超时保护和测试，没有实测）、以及 Windows。

CLI 与 MCP 默认读取匿名档（`user_id=0`）的持仓；要分析某个登录用户的数据，设置 `LOCAL_USER_ID`。

## MCP Server — Claude Code / Cursor 集成

WealthPilot 提供标准 **MCP (Model Context Protocol) Server**，将 59 个投资分析工具直接暴露给 Claude Code、Cursor 等 MCP 客户端。Claude 可以自主调用这些工具获取实时行情和持仓分析——**无需自建 Agent，无需 API Key**（MCP Server 本身不调用 LLM）。

### 配置方法

在项目根目录创建 `.mcp.json`（或在 Claude Code 设置中添加）：

```json
{
  "mcpServers": {
    "wealthpilot": {
      "command": "uv",
      "args": ["run", "--directory", "/path/to/wealthpilot/backend", "python", "-m", "wealthpilot", "mcp"]
    }
  }
}
```

配置后重启 Claude Code，即可在对话中使用 WealthPilot 的全部工具：

```
> 查一下 007340 的最新净值和近 30 天走势

Claude 会自动调用:
  → get_fund_info("007340")
  → get_nav_history("007340", 30)
然后基于返回数据生成分析回答
```

## Deployment

### 本地开发

```bash
make setup && make dev
```

### Docker Compose（自部署）

```bash
cp backend/.env.example backend/.env
# 编辑 .env 填入 API Key
docker compose up --build -d
```

一个容器、一个端口：镜像里先构建网页版，再由后端把页面和接口一起发出去，打开 http://localhost:8000 即可（和本机运行是同一个地址，不再有单独的前端容器和 nginx）。适合放在一台不休眠的机器上全天候跑盯盘，再从自己的电脑用 `wealthpilot --server http://那台机器:8000` 连过去。

- **数据**都在 `wealthpilot-data` 这个卷里（挂在容器的 `/data`）：数据库、技能文件、缓存。自带的两个示例技能第一次启动时会放进去，已有的不覆盖。
- **配置**通过 `backend/.env` 以环境变量传入，改完 `docker compose up -d` 生效。容器里不能用网页上的「设置」页改配置：那个接口只允许本机访问，而且环境变量的优先级更高。
- **升级**：`git pull && docker compose up --build -d`。数据在卷里不受影响，数据库的新字段启动时自动补上。容器里没有源码仓库，所以 `wealthpilot update` 和页面上的更新提示在这里不适用（「版本与自检」会直接告诉你用上面这条命令）。
- **从旧版升级**：以前是 `backend` 和 `workbench` 两个容器（页面在 5180）。数据卷沿用同一个，数据库位置不变；第一次请加 `--remove-orphans` 清掉旧容器：`docker compose up --build -d --remove-orphans`。
- **谁能访问**：端口默认对本机所有网卡开放，而未登录时用的是匿名档。放在有别人能连到的网络上时，请在前面加一层带认证的反向代理，或把端口映射改成 `127.0.0.1:8000:8000`。

这套 Docker 配置是按本机实际跑通的目录结构写的（用同样的布局和环境变量在本机模拟过：页面、接口、技能目录、数据库位置都对），但镜像本身没有在 Docker 里构建和运行过。

### 后端与工作台分开部署

1. 后端：任意能跑容器的平台（如 Railway），Root Directory = `backend`，设置模型 Key 与 `JWT_SECRET`，并把 `FRONTEND_URL` 设为工作台的域名（CORS 白名单）
2. 工作台：`cd workbench && VITE_API_URL=https://你的后端域名 npm run build`，把 `dist/` 放到任意静态托管

只部署后端时用 `backend/Dockerfile`（只有接口，不含页面）；仓库根目录的 `Dockerfile` 是页面和接口合一的那个。

推送到 `main` 后由 `.github/workflows/deploy.yml` 自动构建演示版并发布，不需要后端。
