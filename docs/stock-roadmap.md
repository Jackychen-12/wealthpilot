# 股票能力规划

WealthPilot 现在以 **A 股个股为主导**，基金保留为持仓的一种。这份文档记录股票能力做到了哪一步、还差什么。

## 进度

| 阶段 | 状态 |
|---|---|
| 一、补齐历史行情 | **已完成** —— 股票 / ETF 走前复权日线，回撤、相关性、健康度、压力测试已覆盖 |
| 二、个股工具 | **已完成** —— 行情、日线、业绩、行业，加上多期财务指标、估值历史分位、同行对比、技术指标、公告、分红 |
| 三、并入组合层分析 | **部分完成** —— 穿透已合并直接持股、回测已支持股票；行业自动归因、单票上限约束未做 |
| 四、工作台页面 | **已完成** —— 今日首页、全局搜索、个股多标签详情、自选股、选股器、研究记录 |
| 外部 MCP 连接器 | **已完成入口** —— 只读接入，交易类工具硬性屏蔽；未预置任何厂商 |
| 五、股票主导的 Agent 架构 | **已完成** —— 证券解析前置；Agent 由"按资产分"改为"按研究维度分"（基本面 / 估值 / 走势 / 行业 / 选股 / 组合 / 基金）；四个研究模板；Critic 新增章节完整、财务数字带报告期、禁止目标价三条规则 |
| 六、选股 | **已完成** —— 全市场估值与业绩快照（每日缓存）、条件筛选、行业涨跌排行、市场涨跌家数 |
| 七、评测 | **已完成首版** —— 12 题，新旧架构各跑一次：通过 4 → 9，未发布 1 → 0，平均耗时 25.7 → 36.8 秒 |

## 还没做的

- **资金流向**：东方财富 push2 接口实测频繁断连，没有找到稳定的免费替代，暂不做。
- **行业自动归因**：持仓里的股票目前靠录入时带出的行业标签，没有按行业自动汇总暴露。
- **单票上限约束**：风险画像里还没有"单只股票不超过 X%"这一条。
- **港股、美股**：代码结构预留了市场前缀，未接数据。
- **评测集**：只有 12 题、每版一次；需要扩到 20 题以上并多次取平均才能当回归基线用。
- **深度研究的耗时**：一次要跑四个 Agent，约 60 秒。

下面是最初的规划全文，保留作为后续工作的依据。"现状"一节描述的是动工之前的情况。

## 现状（动工前）

持仓表已经支持 `asset_type = stock / etf / crypto`，但只打通了"取最新价"这一环：

| 环节 | 基金 | 股票 / ETF |
|---|---|---|
| 最新价、市值、持有收益 | 有（天天基金净值） | 有（新浪实时行情） |
| 历史价格序列 | 有（净值历史） | **没有** —— 历史接口只认基金代码 |
| 回撤、Sharpe、相关性、健康度 | 有 | **算不出来**，依赖历史序列 |
| 规则回测 | 有 | **没有** |
| 基本面（估值、财务、行业） | 经理、基准、阶段收益 | **没有** |
| Agent 工具 | 19 个，入参都是 `fund_code` | 没有任何个股工具 |
| 持仓穿透 | 把基金拆到重仓股 | 直接持有的个股没有并入穿透结果 |
| 工作台页面 | 基金查询、回测等 | 没有个股页面 |

结论：现在往持仓里放一只股票，总览页的市值是对的，但风险体检、相关性、回测都会悄悄把它漏掉。第一步必须先解决这个"悄悄漏掉"。

## 原则

沿用基金这条线已经验证过的做法，不为股票另开一套：

- **算术不交给模型**。估值分位、涨跌幅、均线，全部由工具算好再给 Agent。
- **每个数字要有出处**。新工具同样产出带 ID 的证据，Critic 的溯源规则原样适用。
- **取不到就说取不到**。免费行情源不稳定，工具返回"无数据"时回答里必须如实写缺口，不能用常识补。
- **功能页和 Agent 共用工具**。工作台的个股页直接调 `/api/tools/*`，页面和 AI 说的是同一个数。

## 分阶段计划

### 第一阶段：补齐历史行情，让现有分析不再漏掉股票

这是后面所有事情的地基，也是当前最明显的缺陷。

- 新增按资产类型分发的历史价格入口 `fetch_price_history(code, asset_type, days)`：基金走现有净值接口，股票 / ETF 走日 K 线（前复权收盘价），输出统一成现有的 `{nav_date, nav, daily_return}` 结构，这样分析引擎不用改。
- `load_market_context` 改用这个入口，回撤、Sharpe、相关性、健康度、压力测试自动覆盖股票。
- 代码规范化：`600519` / `sh600519` / `600519.SH` 统一成一种内部写法，入库和查询各处一致。
- 取不到历史的持仓，在各分析结果里明确标出"未纳入计算"，而不是静默跳过。

验收：一个"3 只基金 + 2 只股票"的组合，风险体检页五个维度都有值，相关性矩阵是 5×5。

### 第二阶段：个股工具与 StockAgent

- 新工具（归入新的 `STOCK_TOOLS`）：
  - `get_stock_quote` —— 实时行情：价格、涨跌幅、成交额、换手率
  - `get_stock_kline` —— 日 K 线摘要与区间涨跌幅
  - `get_stock_valuation` —— PE / PB / 股息率，及其在自身历史中的分位
  - `get_stock_financials` —— 近几期营收、净利润、ROE、负债率及同比
  - `get_stock_profile` —— 所属行业、主营业务、市值
- 新增 `StockAgent`，与 market / portfolio / risk / quant 并列；Planner 的专家清单和关键词兜底表加上它。
- 现有工具的入参目前叫 `fund_code`。新工具用 `code` + `asset_type`；老工具保持不动，避免一次改动波及全部提示词和测试。
- Critic 的数字溯源已经和资产类型无关，只需要给"指数名里的数字"那类白名单补上股票场景（如"科创50"）。

验收：问"贵州茅台现在估值贵不贵"，回答里的 PE、分位都能点到对应证据，取不到财报时如实写缺口。

### 第三阶段：把直接持股并入组合层分析

- **穿透合并**：直接持有的个股，与基金重仓股里的同一只票合并计算真实暴露。这是基金 + 股票混合持仓最有价值的一个数——"我直接买了茅台，基金里又间接持有多少"。
- **行业归因**：个股按所属行业自动打标签，不再依赖手填的行业字段。
- **集中度与约束校验**：单票上限纳入风险画像（如"单只个股不超过组合 10%"），`check_profile_constraint` 增加这一条。
- **回测**：`backtest_rule` 支持股票代码，计入佣金与印花税，并在局限说明里写清楚未处理停牌和涨跌停。

### 第四阶段：工作台页面

- 新增"个股查询"页，与现有"基金查询"并列：行情、K 线、估值分位、财务摘要，右上角可一键交给 AI 解读。
- 持仓页按资产类型分组展示，录入股票时按代码自动带出名称与行业。
- 持仓穿透页增加"直接持有 + 间接持有"合并视图。
- 导航的"市场与量化"分组下增加自选列表（先存本地，不做推送）。

### 暂不做

- 实时推送与盘中预警（免费行情源做不稳）
- 自动下单、对接券商
- 港股、美股（先把 A 股做扎实；代码规范化那一步会预留市场前缀）
- 技术指标选股、因子模型

## 风险与对策

| 风险 | 对策 |
|---|---|
| 免费行情源限流或改接口（本项目已踩过两次） | 每类数据至少两个源；工具返回里带来源与数据日期；接口改了能被测试第一时间发现 |
| 复权口径不一致导致回撤、回测失真 | 统一用前复权收盘价，并在工具输出里写明口径 |
| 财务数据滞后，模型把旧财报当成现状 | 工具输出带报告期；提示词要求引用时必须转述报告期 |
| 个股问题更容易滑向"推荐买卖" | 沿用画像硬约束；未完成风险测评时不出具体仓位；回答区分事实与判断 |

## 建议的落地顺序

第一阶段单独做完并合入，再开始第二阶段。第一阶段不涉及任何提示词和 Agent 改动，风险最低，而且它修的是一个已经存在的问题——现在放进组合的股票没有被纳入风险计算。
